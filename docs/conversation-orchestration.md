# 对话与任务调度设计建议

状态：设计依据与后续方向。steering、原生事件、交互问题及会话偏好已接入；实际支持范围和架构见 [Claude 原生能力](claude-capabilities.md)。不增加独立 LLM 对话协调层。保留有界 FIFO 队列、独立管理命令、默认 5 秒自动反馈及 4 小时闲置回收。

## 目标与依据

任务运行时仍能接收补充、回答状态问题、明确接纳独立任务。执行代码的任务继续共享一个工作区并保持串行；对话是否能继续，不由工作区锁决定。

OpenClaw 的 [队列模式](https://docs.openclaw.ai/concepts/queue) 和 [会话控制器](https://docs.openclaw.ai/concepts/session-controller) 用明确策略管理 steer、followup、collect、interrupt。它的 [steering](https://docs.openclaw.ai/concepts/queue-steering) 依赖具体运行时支持，不能把该体验简单等同于“额外调用一次 LLM 分类”。

当前安装的 Claude ACP v1 adapter 支持 `_session/steering`，通过初始化响应 `_meta.steering.supported` 声明；Bridge 已按协商能力接入，不仅检查包版本。

## 建议结构

飞书入口 → 规则调度与权限校验 → Claude Code（通过现有 ACP 适配器接入）→ 任务事件与飞书通知。

- 会话控制器负责鉴权、去重、账号/聊天/话题/用户隔离和消息归属。
- 显式命令直接走规则；普通消息空闲时交给 Claude，繁忙时按已选队列策略处理。使用者可显式选择引导当前任务，不使用关键词猜测来自动中断或取消任务。
- 任务管理器负责运行、排队、引导投递、取消、结果记录和工作区互斥。只有该层可提交或改变任务状态。
- 执行器负责实际 Claude 会话与代码工作。模型文字中的“完成了”不能替代任务完成事件。
- 通知层根据真实任务事件发送回执和完成消息；5 秒提示只是无响应时的反馈机制，可配置 10 秒。

## 优先复用 Claude Code 能力

不增加第二套网关、模型、凭据、对话记忆或意图分类调用。需求理解、代码规划、工具执行和执行上下文管理继续交给现有 Claude Code；Bridge 不重新实现这些能力。

| 能力 | 优先采用的方式 |
|---|---|
| 新任务与上下文恢复 | 现有 ACP new/load/prompt，复用 Claude 会话 |
| 当前任务的补充要求 | 检查 adapter 能力后调用原生 steering 扩展 |
| 取消正在执行的任务 | ACP cancel，保留进程清理超时兜底 |
| 工具调用、子 Agent、上下文压缩 | 由 Claude Code 管理，不另写模型调度器；仅在有可靠事件和接口时接入展示 |
| 进度与完成通知 | 读取运行时事件，结合 Bridge 持久化任务状态 |
| 权限、跨用户排队、去重与飞书投递 | 保留在 Bridge，原生会话能力不能替代服务边界 |

先检查现有 ACP 能力与当前安装版本，再考虑 CLI/SDK 的结构化接口；不通过模拟终端按键或解析界面文案补接口。不要同时启动两条执行链路处理同一条消息。某项 CLI 交互能力未被适配器暴露时，应明确记录差距，验证接入方式后再启用。自动回复时机仍按实际耗时判断，默认 5 秒，可设 10 秒。

## steering 的投递契约

管理命令（状态、结果、队列与取消）直接处理，不等待执行任务释放工作区；重置命令即时检查，当前会话有未完成任务则拒绝。其他模型指令继续排队。steering 通过单独能力协商和权限路径，不能将任意斜杠命令视为可抢占任务。

只允许作用于同一用户、账号、聊天和话题的当前任务；默认不允许其他人通过引导修改任务目标。先捕获任务编号、会话 ID 和运行代次，防止请求落到刚启动的下一项任务。

调用 `_session/steering` 时设置 `_meta.steering.idleBehavior: promptRequired`。收到 `injected` 才标记已投递；明确返回 `promptRequired` 时提示未执行，由用户作为普通消息重新发送。超时或断线意味着结果未知，不自动重试为队列任务，以免执行两遍。取消和结果投递阶段拒绝引导。

该扩展可能抢占生成过程，或把正在运行的工具转为后台，因此不能把所有等待项批量注入当前轮次。先通过可控 ACP fixture 验证补充消息的输出、完成信号、取消和断线行为，再接入真实模型。

## 实施状态与后续方向

1. 已增加 `/steer`，普通消息保持 FIFO；不增加与普通消息含义重复的 `/followup`。
2. 已提取原生能力控制、命令解析、事件投影和交互请求模块，Bridge 保留任务生命周期与调度。
3. 已接入工具/计划/用量事件、会话偏好、本人历史恢复和有界附件。独立后台任务、检查点及 worktree 并发需新的生命周期契约和真实运行时验证，当前不宣称支持。

验收应覆盖：忙时仍能查询状态；同会话补充只执行一次；独立任务不混入当前上下文；无权用户不能引导；模型/网络超时不丢消息、不重复执行；任务完成才发完成通知；快速任务无额外回执，长任务只发一次提示。
