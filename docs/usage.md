# 使用与运维指南

面向两类读者：在飞书里使用机器人的用户，以及负责部署后运行、排障的运维者。部署步骤见[部署指南](deployment.md)，实现细节与行为契约见[实现设计](design.md)，环境变量默认值以[配置契约](design.md#配置契约)为准。

## 接入飞书

### 首次扫码创建应用

默认使用扫码创建：首次启动调用飞书官方设备授权流程，二维码仅允许创建新应用，避免覆盖已有机器人的配置。确认页申请机器人发消息、接收私聊和群聊 @消息、读取消息及附件资源、发送/删除表情回复及 CardKit 卡片写入权限，订阅 `im.message.receive_v1`；不申请用户身份权限。确认后保存应用凭据及平台返回的扫码者 open_id，再查询机器人 open_id。若平台未返回扫码者身份，需设置 `ALLOWED_USERS` 后重启。

`FEISHU_APP_NAME` 可配置首次扫码创建的应用名称，默认 `AgentBridge`，留空也使用默认值。Compose 已映射，可在 `.env` 或 Portainer 中设置。该值仅作为创建时的预设名称，最终名称以飞书确认页为准；已有绑定不会被自动改名或重新创建，需要改名时在飞书后台操作。

设置 `FEISHU_SELECT_EXISTING_APP=true`（默认 `false`，Compose 已映射）后，首次扫码确认页同时提供“选择已有应用”入口：扫码者可改为选择自己名下的已有应用，确认页会展示为该应用增量开通上述权限和事件订阅的变更，凭据按同一绑定流程保存。适合想复用已有机器人或已有应用配置的场景；平台对已有应用的审批和发布规则仍以确认页为准。默认关闭以避免误选应用覆盖配置；不确定时保持默认，创建新应用后再在飞书后台调整。

凭据保存在 SQLite 同目录的 `feishu-binding.json`，Docker 默认路径为 `/data/bridge/feishu-binding.json`，随 agent-data 卷持久化。POSIX 文件权限为 0600，日志不输出 App Secret。后续查询机器人身份失败时保留已取得凭据，重启继续处理，不重新创建应用。二维码过期或拒绝授权后会报错，重启可重新扫码；Compose 的重启策略可能自动重试，请扫描日志中最新的二维码。当前仅支持飞书，扫码到 Lark 租户会停止并保留记录。

平台支持范围和租户审批规则可能影响自动配置；请在扫码确认页核对权限及事件。若应用仍待审核、缺机器人能力或无法收消息，需到飞书后台完成发布，并确认事件订阅为长连接。注册流程不绕过平台审批，也不通过 API 强制修改已有应用。

恢复时需注意：已保存凭据但机器人身份查询失败，只需重启继续查询；不要删除绑定文件重新扫码。修改数据库所在目录时，应一并迁移 `feishu-binding.json`。若远端已创建应用、但本地凭据写入失败，请从飞书后台找回应用并改用下述手动配置。绑定文件包含密钥，首次启动日志包含有效期内的授权链接，均应限制访问。

首次启动/绑定状态与 `--check` 的对应关系见[启动状态表](design.md#首次启动与绑定)。

### 手动配置已有应用

已有应用也可以不经扫码直接绑定：两个 Compose 文件均已映射以下四个变量，在 `.env` 或 Portainer 中同时填写非空值即可（本地 Node 直接设置进程环境）；这组配置优先于保存的扫码绑定，不会混用其他应用的用户身份：

```dotenv
FEISHU_APP_ID=cli_your_app
FEISHU_APP_SECRET=your_app_secret
FEISHU_BOT_OPEN_ID=ou_your_bot
ALLOWED_USERS=ou_your_user
```

手动应用需要启用机器人、发布版本，并配置消息权限与事件长连接订阅。任意应用字段已填写但其余缺失会报错，不会静默改成扫码模式。扫码模式可单独设置 `ALLOWED_USERS` 覆盖扫码用户，Compose 已映射该变量。若飞书未返回扫码用户身份，必须通过此项明确指定白名单用户，服务不会将首个发消息的用户自动加入白名单。绑定文件损坏时停止并提示恢复；更换绑定前先停服务、备份并移走该文件。已有飞书应用不会被本服务自动删除。

### 权限与事件清单

| 场景 | 需要的权限/订阅 | 缺失时 |
|---|---|---|
| 收发消息 | 机器人发消息、接收私聊、接收群聊 @、`im.message.receive_v1` 长连接 | 无法收发，需在后台补齐并发布 |
| 图片与文本附件 | `im:message:readonly` | 附件不可下载；首次扫码会申请 |
| Typing 表情 | `im:message.reactions:write_only` | 仍执行任务，不显示 Typing |
| 原生流式卡片 | `cardkit:card:write` | 完成后改用富文本回复 |

已有飞书应用需在后台补充上述权限并发布新版本；重启 Bridge 不会自动修改已有应用授权。首次扫码会申请这些权限，更新服务也不会修改旧应用权限。

### 二维码与授权凭证

授权链接优先显示，同时在等待扫码期间生成固定黑白二维码图片，可复制到本机打开，不受日志字体影响。图片位于 SQLite 同目录，Docker 默认是 `/data/bridge/feishu-qr.svg`。绑定完成、过期或失败后删除图片；图片和链接也属于短期授权凭据。

日志二维码使用整格模块（每格两个字符宽），显式 ANSI 黑白配色、四格白色留白，并在每行重置颜色，减少主题反色和半格字体错位。图案比紧凑字符画更宽，Portainer 查看时需展开日志区域、关闭时间戳和自动换行。日志查看器仍可能改变行距或剥离颜色，无法保证所有版本和字体下都可扫码；剥离颜色后只剩普通字符图案，其颜色取决于查看器主题。

## 消息规则

- 仅接收 `sender_type=user` 的事件。私聊可直接发送；群聊必须 @配置的机器人，移除对应 mention 占位文本后执行。
- 所有消息命令都要求发送者位于 `ALLOWED_USERS`；`ADMIN_USERS` 不自动获得普通消息执行权限。管理员若需要执行命令，也应加入 `ALLOWED_USERS`。
- 支持文本、图片和 UTF-8 文本文件消息；附件仅在白名单校验通过、任务真正执行时下载。图片最多 5 MiB（PNG/JPEG/GIF/WebP），文本附件最多 256 KiB，暂不解析 PDF、Office、压缩包和音视频。
- 会话按用户和话题区分；群聊中的流式卡片和 `/result` 回复仍发到原群聊或话题。同一聊天不同用户使用各自的 Claude 会话，共享项目文件。
- 超长文本会提示拆分；不支持的附件类型会提示暂不支持；不会截断用户指令后执行。

## 命令

以下列表是命令的权威说明。未列出的 slash 指令会作为普通任务发送给 Claude；Bridge 保留命令优先。

### 任务与队列

| 命令 | 行为 |
|---|---|
| `/queue` | 查看本人当前话题的排队任务、编号和前方任务数量；管理员可查看同一话题其他用户的队列 |
| `/cancel` | 取消本人在当前聊天、话题内正在执行的任务，管理员亦可取消；取消后继续下一项 |
| `/cancel <任务编号>` | 取消指定的排队或执行中任务；编号可从回执、`/status` 或 `/queue` 获取；管理员可取消同话题其他用户的任务 |
| `/cancel all` | 清空本人当前话题的排队任务，不取消执行中的任务或其他用户的队列 |
| `/new` | 清除本人当前话题的会话映射，下次新建；该会话有执行中或排队任务时，需等待完成或取消后重置 |

### 结果与状态

| 命令 | 行为 |
|---|---|
| `/result` | 取回本人当前话题最近一次已保存的任务结果，不重新执行任务 |
| `/result <任务编号>` | 取回本人当前话题指定任务的结果 |
| `/result failed` | 取回本人当前话题最近一项投递失败的结果，包括重启时仍待发送的结果 |
| `/status` | 查询当前话题任务的阶段、已用时间、执行时限与最近文字输出时间，不启动模型；管理员可查看同一聊天、话题中的任务状态 |

`/status` 仅对同一应用、聊天、话题下的任务发起人或白名单内管理员展示详情；其他已授权用户只能看到当前会话无任务、工作区忙。同时显示当前会话可查看的排队数量。

### 原生能力

| 命令 | 行为 |
|---|---|
| `/help` | 列出 Bridge 保留命令 |
| `/commands` | 最近一次协商的 Claude 原生命令，包括运行时公布的技能 |
| `/capabilities`、`/config` | 查看能力与配置选项快照，不启动模型 |
| `/tools`、`/plan`、`/usage` | 查看最近工具、计划和用量；没有事件时明确说明，不估算进度 |
| `/steer <要求>` | 引导本人同一聊天/话题正在执行的任务；不会替其他用户修改任务 |
| `/questions` | 重发当前未回答的问题 |
| `/answer <编号> <回答或 JSON>` | 回答指定问题，不进入任务队列 |
| `/skip <编号>` | 明确拒绝回答该问题；由 Claude 决定后续行为 |
| `/sessions` | 列出本人当前聊天和话题最近 20 个会话 |
| `/resume <编号>` | 选择下次恢复的本人历史，需无执行中和排队任务 |
| `/mode plan`、`/mode execute` | 设置后续任务使用原生计划模式或免审批执行模式 |
| `/model <值>`、`/effort <值>` | 设置后续任务偏好，启动时校验原生支持的可选值；`default` 清除 Bridge 覆盖值 |

`/plan` 是查看任务清单；要生成方案，先设置 `/mode plan` 再发送任务。计划模式没有自动批准入口，执行方案前显式发送 `/mode execute` 再下达执行指令。管理查询、回答、跳过和引导不占队列容量。

单字段问题可回复 `/answer <id> SQLite`。多个字段使用 `/answer <id> {"question_0":"SQLite","question_1":"测试环境"}`，字段名和可选值随问题展示。每个问题最长等待 10 分钟，任务总时限仍生效；迟到回答被拒绝。steering、问题回答和会话偏好的完整契约见[Claude 原生能力](claude-capabilities.md)。

Claude 的 `CLAUDE.md`、Skills、Hooks、子 Agent 和已配置插件继续使用原生项目设置。可用 `CLAUDE_RUNTIME_CONFIG` 指定 MCP 与执行限制的 JSON 文件，两个 Compose 已映射该路径；默认传入 `includeCoAuthoredBy: false` 和空的 commit/pr attribution，同时关闭会话链接，不修改 Git 作者信息。格式、凭据管理和能力边界见[Claude 原生能力](claude-capabilities.md)。

## 回复方式

默认 `TASK_REPLY_MODE=auto`：执行不满 5 秒直接返回结果；达到 `TASK_BACKGROUND_NOTICE_MS`（默认 5000，可改为 10000）时发送一次后台执行通知，完成后再发送结果。自动模式不持续显示 Typing 或中间流式卡片，仍可用 `/status` 查询。通知计时从任务实际开始执行算起，不包含排队时间；消息队列接收提示仍即时发送。通知与执行并行，网络故障不会阻塞模型启动，最终结果会等待通知投递结束或超时，避免消息顺序颠倒。这一规则不额外调用 LLM。

`TASK_REPLY_MODE=background` 始终先发后台执行回执；`TASK_REPLY_MODE=stream` 保留流式交互：开始时添加 Typing 表情，完成、失败或取消后移除；有实际输出后每 250 毫秒至多合并更新一次 CardKit 卡片。各模式最终均可创建卡片投递完整回复并关闭流式状态。正文使用飞书 JSON 2.0 Markdown（飞书客户端需 7.20 或更高版本），不添加默认折叠区域，内部 stopReason 不放进回复。

回复按每片最多 3,000 个原文 Unicode 码点拆分，优先在换行处分段，跨段代码围栏会闭合再重新打开。第一段在同一卡片内流式更新，余下段落在完成后按序发送 Markdown 富文本消息。CardKit 创建或正文更新失败时降级为富文本，保留原消息/话题的回复关系。累计输出最多保留末尾 24,000 个码点，超限会明确标注；`/result` 取回同一份已保存结果，不能恢复被截掉的开头。

回复配置由 Compose 映射，修改后需重新创建容器。卡片与表情的实现细节和降级路径见[输出、投递与诊断](design.md#输出投递与诊断)。

## 队列、会话与时限

任务默认允许执行 2 小时，包含会话初始化时间。可在 `.env`、Portainer 或进程环境中设置 `TASK_TIMEOUT_MS`，例如 `10800000` 为 3 小时，最多 24 小时；Compose 已映射该变量，修改后需重新创建容器。任务长时间没有文字输出不会触发额外的空闲超时，工具执行期间可用 `/status` 查询、用 `/cancel` 取消。最近文字输出时间不是工具心跳，也不能用于判断任务卡住。

长任务期间工作区由一个任务独占，后续普通消息按接收顺序排队，最多等待 20 项（不含当前任务）。入队后立即发送任务编号和前方任务数量。当前任务执行结束并保存结果后，队首即可开始执行；取消或失败路径会先清理 Adapter 进程。入队回执和上一项的飞书结果发送可并行进行。取消排队时立即移除任务，等该项入队回执结束或超时后再回复取消确认。每项任务的最终回复会等本项回执和在途进度，多个任务的回复可能按不同于执行的顺序到达。排队时间不计入执行时限，任务启动时才恢复会话并开始计时。队列满时明确告知本条未接收。

管理命令走独立处理路径，不占队列容量，队列满时仍可查询状态、查看结果、取消执行中或排队任务。`/new` 立即检查当前会话，存在未完成任务时提示先取消，不会插入普通任务队列。其他发给 Claude 的项目指令仍按普通任务执行，不能借命令形式绕过工作区互斥。

同一用户和话题的 Claude 会话从任务结束、结果落库并刷新会话时间后开始计算闲置时间，满 4 小时后下次任务创建新会话；连续工作可复用上下文。可用 `SESSION_IDLE_TIMEOUT_MS=14400000` 配置（范围 1 分钟至 7 天），两个 Compose 文件均已映射。`/status`、`/queue`、`/result` 不延长会话有效期。全局无执行中和排队任务满该时长时，也停止闲置 Adapter 进程；运行中的长任务不受闲置回收影响。排队任务在实际启动时判断会话是否过期，排队等待本身不刷新有效期。回收仅清除 Bridge 映射及空闲进程，保留任务结果和 Claude 历史文件。

关闭飞书客户端不影响任务执行。服务停止或进程清理失败时，等待项会中断并尽力通知；异常退出后重启也会将等待项标记中断，可用 `/result` 查看当前会话最近记录。排队提示正文仅保存在内存，不会在重启后自动重放；需要执行时重新发送。当前不跟踪 Claude 结束本轮后遗留的后台命令，也不自动续跑中断任务。

## 结果投递与保留

对符合接入规则且在白名单内的发送者，最终结果与任务终态先事务保存，再投递。可恢复网络错误和限流最多尝试 3 次，总发送窗口 15 秒，使用稳定分片 UUID 去重，不重放 Agent prompt。服务重启后不自动补发，可用 `/result` 取回。数据库本身不可写时无法保证结果落盘，会记录脱敏错误。

每次启动会在接收新任务前，按 `DATA_RETENTION_MS`（默认 30 天，范围 1 天至 365 天，Compose 已映射）清理超过保留期的消息去重、任务、结果与会话历史行。`/result` 可取回仍保存在数据库中的结果。运行期间超过保留期的结果会在下次启动时清理。需要长期留存时请备份或延长保留期。

## 常见问题

| 现象 | 处理 |
|---|---|
| 扫码确认后机器人无响应 | 到飞书后台确认应用已发布、机器人能力已启用、事件订阅为长连接；查看服务日志有无启动错误 |
| 二维码无法扫描 | 使用日志中的授权链接，或打开 SQLite 同目录的 `feishu-qr.svg`（Docker 默认 `/data/bridge/feishu-qr.svg`）；展开 Logs、关闭时间戳和自动换行 |
| 重启后仍需扫码 | 检查 `DATABASE_PATH` 所在目录是否变化；绑定文件必须跟数据库同目录并一起迁移。不要删除绑定文件 |
| 已有机器人无法接收附件 | 后台补充 `im:message:readonly` 并发布新版本；重启不会自动补权限 |
| 不显示 Typing，或流式卡片不更新 | 先确认 `TASK_REPLY_MODE=stream`。默认 `auto` 模式下这两项不显示。已开启流式模式时，检查 `im:message.reactions:write_only` 和 `cardkit:card:write`，补齐缺失权限后发布应用版本。缺卡片权限时会降级为富文本 |
| 任务长时间无结果 | 用 `/status` 查看阶段和最近输出，用 `/cancel` 取消；确认未超过 2 小时执行时限 |
| 结果未送达飞书 | 用 `/result` 或 `/result failed` 取回；检查日志中的投递错误分类和网络 |
| 容器重启导致任务中断 | 预期行为：重启不重放任务，用 `/result` 查看最近结果后重新发送 |
| 提示绑定文件损坏 | 停服务、备份并移走绑定文件，然后重新扫码 |
| 手动配置不全 | 补齐 App ID、App Secret、Bot open_id 和 ALLOWED_USERS 四项；或清空三个应用字段后改用扫码 |
